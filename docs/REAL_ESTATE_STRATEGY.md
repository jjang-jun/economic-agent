# 부동산 저점 매수 전략

## 목표

최종 목표는 2028~2029년 전후 서울·경기 아파트를 **저점에 가까운 매수 검토 구간에서 감당 가능한 합리적 가격으로 매수**하는 것이다.

- 상시 관찰 가격대: 5.8억~9.5억원
- 우선 목표 가격대: 8.5억~9.5억원
- 희망 대출: 최대 6억원
- 전제: 부부 기준 생애최초·실거주 목적

정확한 최저가는 사후에만 확인할 수 있다. 시스템은 `바닥 확정`이나 자동 매수를 출력하지 않고, 가격·거래량·전세·호가·금융여력을 교차검증한 **매수 검토 구간**을 제시한다.

## 데이터 계층

1. 국토교통부 실거래가: 아파트 매매 계약과 계약해제, 전월세 계약
2. 한국부동산원: 지역별 가격지수·거래 통계의 보조 기준(후속 연동)
3. 호가: 이용 권한이 있는 외부 feed 또는 사용자 입력만 사용
4. 금융: 당시 LTV·DSR·가격구간별 한도와 가구 소득·기존 부채
5. 정성 지표: 교통, 직주근접, 학군, 공급, 정비사업, 생활권(후속 모델)

국토교통부 공개자료는 계약일 기준이며 신고·정정·해제가 뒤늦게 반영될 수 있다. 따라서 매일 03:20 KST에 최근 2개월을 재조회하고, 당월 수치가 완결된 통계라고 표현하지 않는다.

호가는 실거래와 다른 데이터다. 동일 매물의 중복, 미끼·철회 매물, 층·향·수리상태 차이를 포함하므로 `verified`와 출처를 보존한다. 공식 공개 호가 API가 없는 플랫폼을 무단 크롤링하지 않는다. `REAL_ESTATE_LISTING_FEED_URL`은 계약·허가받은 JSON feed가 있을 때만 03:50 KST 작업을 활성화한다.

## 매수 검토 게이트

아래 다섯 조건을 별도 점수로 유지한다. 하나의 숫자로 섞어 근거를 숨기지 않는다.

1. 가격: 동일 지역·단지·면적의 중위 실거래가가 고점 대비 충분히 조정됐는가
2. 거래: 가격 급등 없이 거래량이 저점에서 회복되는가
3. 호가: 최저 유효 호가와 최근 실거래 간 괴리가 좁아지고 협상 가능한가
4. 전세: 전세가율과 전세 거래가 매매가격의 하방을 지지하는가
5. 금융·현금: 실제 DSR 심사 후에도 계약금·잔금·취득부대비용·비상자금을 감당하는가

초기 시장 상태는 다음처럼 제한한다.

- `INSUFFICIENT_SAMPLE`: 표본 부족
- `CORRECTION_CONTINUES`: 가격과 거래가 함께 약해 하락 지속 가능성
- `STABILIZING`: 가격 변동이 좁아지고 거래 급감이 멈춤
- `TRANSACTION_RECOVERY_WATCH`: 가격 추격 없이 거래가 회복되어 현장 조사 가치가 생김
- `CHASE_RISK`: 가격과 거래가 함께 급증해 추격 위험이 큼
- `NEUTRAL`: 위 조건에 아직 해당하지 않음

`TRANSACTION_RECOVERY_WATCH`도 매수 신호가 아니다. 목표 단지 현장 확인, 등기·권리 검토, 대출 사전심사, 실거주 품질 검토를 시작할 근거일 뿐이다.

## 현재 자동화

```text
03:20 KST (매일, 설정 시)
  국토교통부 서울·경기 매매/전월세 최근 2개월 재수집
  -> 5.8억~9.5억 매매 저장
  -> 전월세 비교 자료 저장
  -> 지역·월별 거래량/중위가격/전세가율/해제비율 계산
  -> 주택 목표와 가격대별 대출 시나리오 저장

03:50 KST (허가받은 feed 설정 시에만)
  호가 스냅샷 저장

월요일 04:10 KST (R-ONE 키 설정 시)
  한국부동산원 월간 아파트 매매가격지수 24개월 재조회
  -> 서울·경기 지역별 1·3·12개월 변화와 24개월 고점 대비 낙폭 저장
```

명령:

```bash
npm run real-estate:collect -- --dry-run
npm run real-estate:collect -- --regions=11680,11710 --months=202608,202607
npm run real-estate:backfill -- --months=24
npm run real-estate:reb:collect -- --dry-run
npm run real-estate:listings:collect -- --dry-run
```

최초 운영 전에는 공공데이터포털에서 국토교통부 아파트 매매·전월세 API를 각각 활용신청한 뒤 **Decoding 인증키**를 `PUBLIC_DATA_API_KEY`에 넣는다. 이미 `DATA_GO_KR_API_KEY`가 있으면 같은 계정의 키를 재사용할 수 있지만 두 API의 활용 승인은 별도 확인한다. DB migration을 적용한 뒤 `REAL_ESTATE_COLLECTION_ENABLED=true`로 전환한다.

R-ONE은 한국부동산원 사이트에서 별도의 인증키와 호출 URL을 등록해야 한다. `REB_OPEN_API_KEY` 설정 전에는 작업이 실패하도록 닫혀 있으며, 표본이 바뀌는 지수와 실제 계약가격을 같은 수치로 취급하지 않는다.
